00

Prima di iniziare

Cosa procurarti e — soprattutto — cosa salvare prima di formattare.

⚠ Attenzione ai dati

Riformattare cancella tutto il disco di sistema. Se i tuoi film e serie sono sul disco interno, copiali altrove prima. Se stanno su un disco dedicato, durante il partizionamento (Fase 04) fai attenzione a non selezionarlo.

Ordine consigliato

Segui le fasi in sequenza. Checkpoint chiave: dopo la Fase 13 verifica che lo stack sia su (docker compose ps → tutti «Up») prima di passare a Backup (15) e Wake-on-LAN (16). Così, se qualcosa non parte, lo isoli con meno pezzi in gioco.

01

Scaricare Debian

L'immagine ufficiale di Debian stable (dal 12 in poi) include già il firmware non-free per il Wi-Fi AX200 e la GPU AMD. Niente immagini "unofficial".

  1. https://www.debian.org/download

    Ti dà debian-<versione>-amd64-netinst.iso (~750 MB). Link diretto: cdimage.debian.org/debian-cd/current/amd64/iso-cd/ — è il server ufficiale Debian (listing spartano ma autentico).

  2. sha256sum -c --ignore-missing SHA256SUMS
02

Chiavetta USB avviabile

Su Fedora/Linux non serve installare nulla. La scrittura sovrascrive tutta la chiavetta (il suo filesystem attuale è irrilevante). Basta una USB da 2 GB+.

  1. Apri Dischi → seleziona la USB → menù ☰ → "Ripristina immagine disco…" → scegli la ISO → Ripristina.

  2. lsblk -o NAME,SIZE,MODEL,TRAN         # individua la USB (TRAN=usb)
sudo dd if=debian-*-amd64-netinst.iso of=/dev/sdX bs=4M status=progress oflag=direct conv=fsync

    ⚠ Device giusto

    Usa il disco intero (/dev/sdb), non una partizione, e verifica due volte con lsblk: il device sbagliato = dati cancellati.

    Su Windows/Mac invece usa balenaEtcher.

03

BIOS, avvio da USB e Wake-on-LAN

Si fa una volta sola, con monitor e tastiera collegati. Approfittane per abilitare il Wake-on-LAN mentre sei nel BIOS.

  1. Canc apre il BIOS, F7 il menù di avvio rapido.

  3. Serve per accendere il server dal telefono (Fase 16). Il WoL richiede la rete via cavo.

Se la USB non compare nel menù

Se nel menù di avvio (F7) vedi solo l'SSD e non la USB, quasi sempre non è stata scritta come avviabile. Da un PC verifica con lsblk -f che la chiavetta mostri iso9660 + vfat; se no, riscrivila (GNOME Dischi «Ripristina immagine disco» o dd). Se invece compare due volte, scegli la voce con «UEFI:». Controlla anche Fast Boot = Disabled e prova un'altra porta USB (2.0).

04

Installazione Debian (senza desktop)

Obiettivo: un sistema headless, solo SSH. Leggero e stabile.

  3. Perché

    Root vuota → Debian configura sudo per il tuo utente. È già l'account amministrativo dedicato delle routine da VPS.

  4. ⚠ Disco giusto

    Scegli l'SSD interno (~500 GB), non il WD Red da 4 TB dei media. Schema «Tutti i file in una partizione»: Docker tiene tutto in /var/lib/docker, quindi una partizione unica evita che un /var separato si riempia e pianti lo stack.

    • Nazione mirror: Italia → poi deb.debian.org se proposto (CDN ufficiale), altrimenti il mirror italiano di default.
    • Proxy HTTP: lascialo vuoto.

  6. spazio per spuntare/togliere. Via «Debian desktop environment» e «GNOME».

  7. GRUB è il bootloader (avvia Linux all'accensione). Rispondi Sì e installalo sull'SSD di sistema (es. /dev/nvme0n1). Alla schermata «Installazione completata»: togli la USB e riavvia → parte Debian dall'SSD.

05

Primo accesso e IP fisso

Il primo comando (trovare l'IP) lo fai sul mini PC col monitor attaccato; poi passi al portatile via SSH e da lì in poi (Fase 06→) scolleghi monitor e tastiera.

  1. ip -4 addr show scope global
ip link    # annota il MAC: ti serve per WoL e prenotazione DHCP
  2. ip route | grep default   # indirizzo del router, es. 192.168.1.1
    • Browser → indirizzo del router → login admin (etichetta sul router, non la password Wi-Fi).
    • Sezione (varia per marca): Fritz!Box «Assegna sempre lo stesso IPv4»; TP-Link → Address Reservation; Netgear → Address Reservation; router ISP → «IP statico / Prenotazione indirizzi / Associazione IP-MAC».
    • Riconosci il mini PC dall'hostname mediaserver o dal MAC, assegna l'IP fisso, Salva.
    sudo dhclient -r && sudo dhclient   # applica il nuovo IP (oppure: sudo reboot)

    Se il router non lo permette

    Imposta l'IP statico su Debian in /etc/network/interfaces (IP fuori dal pool DHCP), poi sudo systemctl restart networking.

  3. ssh TUO_UTENTE@IP_DEL_MINIPC

Wi-Fi → Ethernet (consigliato)

Cavo e Wi-Fi hanno MAC diversi: passando a Ethernet rifai la prenotazione DHCP per il MAC cablato, assegnandogli lo stesso IP (così non tocchi .env). Il Wake-on-LAN funziona solo su cavo → Fase 16 dopo il passaggio. Lo stack Docker non cambia. Qualsiasi presa Ethernet della stessa rete va bene (l'IP segue il dispositivo, non la presa).

Le porte Ethernet non sono preconfigurate (headless): vanno alzate e configurate.

sudo apt install -y ethtool
for i in $(ls /sys/class/net | grep -E '^e'); do sudo ip link set "$i" up; done
for i in $(ls /sys/class/net | grep -E '^e'); do echo -n "$i: "; sudo ethtool "$i" 2>/dev/null | grep -i "link detected"; done
# configura quella con "yes" (es. enp2s0):
printf '\nallow-hotplug enp2s0\niface enp2s0 inet dhcp\n' | sudo tee -a /etc/network/interfaces
sudo ifup enp2s0
ip -4 addr show enp2s0

Debian 13: se manca dhclient («comando non trovato»): sudo apt install -y isc-dhcp-client, poi sudo ifdown enp2s0; sudo ifup enp2s0. Nel router compaiono due voci «mediaserver» (Wi-Fi + Ethernet): prenota quella Ethernet (dal MAC/IP). Verificato l'SSH sull'IP cablato, spegni il Wi-Fi: sudo apt install -y rfkill && sudo rfkill block wifi (anche rfkill non è preinstallato).

Test connettività: su alcune reti l'ICMP è filtrato, quindi ping 8.8.8.8 può fallire anche con internet ok. Verifica con curl -sI https://deb.debian.org (deve tornare HTTP/...), non con ping.

06

Aggiornamenti e firmware

Sistema aggiornato, firmware AMD/Wi-Fi, strumenti base.

  1. sudo apt update && sudo apt full-upgrade -y
  2. sudo apt install -y firmware-amd-graphics amd64-microcode \
  curl git ca-certificates

    Se «package not found»

    Abilita non-free-firmware (funziona sia su Debian 13+ deb822 sia su Debian 12):

    # Debian 13+ (deb822)
if [ -f /etc/apt/sources.list.d/debian.sources ]; then
  sudo sed -i '/^Components:/{/non-free-firmware/!s/$/ non-free-firmware/}' \
    /etc/apt/sources.list.d/debian.sources
fi
# Debian 12 (classico)
if [ -f /etc/apt/sources.list ]; then
  sudo sed -i '/^deb .*debian/{/non-free-firmware/!s/$/ non-free-firmware/}' \
    /etc/apt/sources.list
fi
sudo apt update
07

🛡️ Blindare l'accesso SSH

La misura che conta di più: dall'accesso con password a quello con chiave.

Modello di rischio

Server in LAN dietro NAT: finché non fai port-forwarding, da internet non entra nessuno — il router è il firewall vero. L'hardening è difesa in profondità. Regola d'oro: mai inoltrare le porte dei servizi sul router.

  1. ssh-keygen -t ed25519 -C "mediaserver"
ssh-copy-id TUO_UTENTE@IP_DEL_MINIPC

    Verifica di entrare senza password.

  2. ⚠ Non chiuderti fuori

    Solo dopo aver verificato il login con chiave; tieni aperta una seconda sessione.

    sudo tee /etc/ssh/sshd_config.d/99-hardening.conf >/dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
EOF
sudo systemctl restart ssh
08

🛡️ Firewall, Fail2ban e router

Chiudi tutto ciò che non serve; lascia passare solo la LAN; blinda il router.

  1. sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp   # adatta la subnet
sudo ufw enable

    Docker aggira ufw

    Le porte pubblicate dai container sono aperte in iptables e ufw non le filtra. Va bene: le vuoi in LAN, il router le tiene fuori da internet.

  2. sudo apt install -y fail2ban
sudo tee /etc/fail2ban/jail.local >/dev/null <<'EOF'
[sshd]
enabled  = true
backend  = systemd
maxretry = 5
findtime = 10m
bantime  = 1h
EOF
sudo systemctl enable --now fail2ban

    Onestamente

    Con l'accesso a sola chiave il brute-force è già impossibile: Fail2ban qui è «cintura + bretelle».

  3. I servizi non hanno login: restano al sicuro finché raggiungibili solo dalla LAN. Nel router:

    • UPnP (in Advanced/NAT/Firewall) → disattiva: evita che app/dispositivi aprano porte verso internet da soli.
    • Port Forwarding (Virtual Servers / Inoltro porte) → nessuna regola verso il mini PC o le sue porte.
    • DMZ → disabilitata. Se non trovi la voce, non è attiva (va abilitata di proposito) → ok.

    Controprova opzionale: dal telefono in rete mobile apri http://TUO_IP_PUBBLICO:8096 → non deve rispondere.

09

🛡️ Auto-update e ottimizzazioni

Aggiornamenti di sicurezza automatici e qualche ritocco.

  1. sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

    Riavvio automatico disattivato di default: la macchina non si riavvia da sola mentre guardi.

  2. sudo mkdir -p /etc/systemd/journald.conf.d
printf '[Journal]\nSystemMaxUse=200M\n' | sudo tee /etc/systemd/journald.conf.d/size.conf
sudo systemctl restart systemd-journald
sudo systemctl enable --now fstrim.timer
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swappiness.conf
sudo sysctl --system

Installare Docker

Dal repository ufficiale Docker, con rotazione dei log.

  1. sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: $(. /etc/os-release && echo "$VERSION_CODENAME")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
  2. sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
  3. sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
EOF
sudo systemctl restart docker
  4. sudo usermod -aG docker $USER
# esci e rientra, poi:
docker run --rm hello-world

Driver VAAPI (transcoding)

  1. sudo apt install -y mesa-va-drivers vainfo
sudo usermod -aG render,video $USER   # poi esci e rientra

12

Preparare lo storage (disco esterno)

I media stanno su un disco esterno in /mnt/media. Root unica sullo stesso disco = hardlink.

  1. lsblk -f    # trova il device (es. /dev/sda1) e il filesystem

    ext4 obbligatorio

    exFAT non supporta gli hardlink, NTFS gestisce male i permessi. Se non è ext4 va formattato — salva prima i dati.

    sudo mkfs.ext4 -L media /dev/sdX1   # il TUO device — cancella il disco!
  2. sudo mkdir -p /mnt/media
UUID=$(sudo blkid -s UUID -o value /dev/sdX1)
echo "UUID=$UUID  /mnt/media  ext4  defaults,nofail,x-systemd.device-timeout=30  0  2" \
  | sudo tee -a /etc/fstab
sudo systemctl daemon-reload   # CON sudo
sudo mount /mnt/media
findmnt /mnt/media             # deve mostrare /dev/sdX1

    Tienilo collegato

    Se all'avvio non è montato, i container scriverebbero nella cartella vuota sull'SSD.

    Insidie viste sul campo

    nofail fa fallire il mount in silenzio: verifica sempre con findmnt /mnt/media (se vuoto = non montato). I box USB si svegliano in ~5-6s: monta esplicito sudo mount /dev/sdX1 /mnt/media e guarda sudo dmesg | tail. Un ext4 montato ha sempre lost+found: se ls non lo mostra, non è montato. daemon-reload vuole sudo.

  3. sudo mkdir -p /mnt/media/torrents/{movies,tv} \
             /mnt/media/media/{movies,tv}
sudo chown -R $USER:$USER /mnt/media

  4. Il box USB va in standby: così Docker attende il mount di /mnt/media e non scrive mai sull'SSD (il timeout=30 in fstab dà già tempo al risveglio). Richiede Docker già installato (Fase 10).

    sudo mkdir -p /etc/systemd/system/docker.service.d
printf '[Unit]\nRequiresMountsFor=/mnt/media\n' | \
  sudo tee /etc/systemd/system/docker.service.d/require-media.conf
sudo systemctl daemon-reload

Scaricare e configurare la v2

Cloni il repository, compili .env e avvii lo stack (il transcoding è già attivo nel compose).

  1. git clone https://github.com/giacomorossi-dev/media-server.git
cd media-server
git checkout v2
  2. cp .env.example .env
id -u    # -> PUID
id -g    # -> PGID

  3. ⚠️ Non è un comando da incollare: apri nano .env e imposta questi valori:

    • PUID / PGID = il tuo id -u / id -g (di solito 1000)
    • MEDIA_ROOT=/mnt/media (già impostato)
    • SERVER_IP = l'IP fisso prenotato del mini PC
    • HOMEPAGE_ALLOWED_HOSTS = quell'IP seguito da :3000
    • RENDER_GID / DOCKER_GID = i GID dalla Fase 11 (getent group render / getent group docker)

    Salva con Ctrl+O → Invio → Ctrl+X.

  4. Non devi più modificare il compose: il transcoding è attivo di default. Basta che RENDER_GID sia impostato nel .env (passo precedente) — altrimenti docker compose si ferma con un messaggio chiaro. Su hardware senza iGPU, commenta il blocco devices:/group_add: del servizio jellyfin.

  5. docker compose up -d
docker compose ps

☁️ Backup su cloud

Backup cifrato dei config su Cloudflare R2, che parte all'accensione ed è visibile in Homepage. Dettagli in BACKUP.md.

  1. dash.cloudflare.com → R2 → crea bucket mediaserver-backup; poi «Manage API Tokens» → token con Object Read & Write. Annota Access Key, Secret ed endpoint https://<ACCOUNT_ID>.r2.cloudflarestorage.com.

  2. sudo apt install -y restic
openssl rand -base64 24    # genera la passphrase di cifratura
sudo tee /etc/mediaserver-backup.env >/dev/null <<'EOF'
export RESTIC_REPOSITORY="s3:https://<ACCOUNT_ID>.r2.cloudflarestorage.com/mediaserver-backup"
export RESTIC_PASSWORD="LA_PASSPHRASE"
export AWS_ACCESS_KEY_ID="R2_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="R2_SECRET_ACCESS_KEY"
EOF
sudo chmod 600 /etc/mediaserver-backup.env

    🔑 Passphrase

    Salvala in un password manager, separata dal server: senza, i backup cifrati sono irrecuperabili.

  3. sudo ./scripts/backup-config.sh
source /etc/mediaserver-backup.env && restic snapshots
  4. sudo tee /etc/systemd/system/mediaserver-backup.service >/dev/null <<EOF
[Unit]
Description=Backup config media server (restic)
After=network-online.target docker.service
Wants=network-online.target
[Service]
Type=oneshot
ExecStart=$(pwd)/scripts/backup-config.sh
EOF
sudo tee /etc/systemd/system/mediaserver-backup.timer >/dev/null <<'EOF'
[Unit]
Description=Backup config all'accensione
[Timer]
OnBootSec=5min
[Install]
WantedBy=timers.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now mediaserver-backup.timer

    Guardia

    Lo script salta se l'ultimo backup riuscito è < 20h: più accensioni al giorno = un solo backup.

16

📱 Accensione da telefono

Accendi con il Wake-on-LAN (BIOS già fatto alla Fase 03) e spegni via SSH.

  1. sudo apt install -y ethtool
IFACE=$(ip -o -4 route show default | awk '{print $5}')
sudo tee /etc/systemd/system/wol.service >/dev/null <<EOF
[Unit]
Description=Abilita Wake-on-LAN su $IFACE
After=network-online.target
[Service]
Type=oneshot
ExecStart=/usr/sbin/ethtool -s $IFACE wol g
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now wol.service
  2. echo "$USER ALL=(root) NOPASSWD: /usr/bin/systemctl poweroff" | sudo tee /etc/sudoers.d/poweroff
sudo chmod 0440 /etc/sudoers.d/poweroff
    • App «Wake on LAN»: magic packet al MAC del server.
    • App SSH (Termius/JuiceSSH, con chiave): comando salvato sudo systemctl poweroff.

Il collaudo end-to-end.

Uso quotidiano

Finito. Accendi (anche da telefono) → i container ripartono da soli e il backup gira → guardi → spegni con sudo systemctl poweroff (arresto pulito: i container si fermano bene). Rilanci docker compose up -d solo dopo aver cambiato configurazione o versioni.
